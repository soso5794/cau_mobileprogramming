# 이메일 인증을 통한 비밀번호 재설정

로그인 → 비밀번호를 잊으셨나요? → 가입한 이메일 → 인증번호 받기 → 메일의 6자리 코드와 새 비밀번호/확인 → 변경 → 새 비밀번호 로그인.

## 현재 범위

기존 로컬 계정의 비밀번호를 복구합니다. 가입했던 기기·브라우저·웹 주소에서 실행해야 하며, 프로필·설문·즐겨찾기·캘린더는 유지됩니다. 서버에는 회원 DB가 없으며 메일 소유권만 검증합니다. 다른 기기 복구/서버 인증/가입 시 이메일 인증은 포함하지 않습니다. 로컬 데이터 자체가 삭제된 경우 이 기능으로 되살릴 수 없습니다.

가입 시 소유권 확인이 없었던 계정도 해당 이메일의 소유자만 복구할 수 있습니다. 향후 서버 계정으로 전환할 때 가입 인증·서버 비밀번호 저장·세션 폐기를 함께 구현해야 합니다. 현재 로컬 저장소를 직접 수정할 수 있는 사용자를 방어하는 운영용 인증 시스템은 아닙니다.

## SMTP 설정 (OpenAI 키 불필요)

`server/.env`에 발신 계정 정보를 입력합니다. 이 파일은 Git에서 제외됩니다. 비밀번호를 채팅·Flutter 코드·GitHub에 넣지 마세요. 기존 `.env`를 덮어쓰지 마세요.

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=발신계정@gmail.com
SMTP_PASSWORD=앱비밀번호
SMTP_FROM=발신계정@gmail.com
```

Gmail은 해당 계정에 2단계 인증을 설정한 뒤 앱 비밀번호를 발급하여 사용합니다. 계정 정책에 따라 앱 비밀번호를 사용할 수 없을 수 있으므로 그 경우 허용된 다른 SMTP 제공업체를 사용하세요. 위 이메일은 수신자가 아닌 **발신자**이며, 수신자는 앱에서 입력하는 가입 이메일입니다. Gmail 앱 비밀번호는 표시용 공백 없이 입력하세요. 다른 서비스는 해당 서비스가 허용한 발신 주소/SMTP 설정을 사용합니다.

- [Google 앱 비밀번호 안내](https://support.google.com/accounts/answer/185833?hl=ko)
- [Nodemailer SMTP 설정](https://nodemailer.com/smtp): 465는 TLS, 587은 STARTTLS 필수로 연결합니다. 인증서 검증은 비활성화하지 않습니다.

저장 후 저장소 루트에서 서버를 실행/재시작합니다.

```sh
cd server
npm ci
npm start
```

다른 터미널에서 앱을 실행합니다.

```sh
bash tool/run_web.sh
# 일반 Chrome의 같은 프로필에서 http://localhost:7363 열기
```

`http://127.0.0.1:8787/health`의 `mailConfigured: true`는 설정값이 있다는 뜻이며 실제 인증·발송·수신 성공을 보장하지 않습니다. 실제 수신은 앱에서 발송한 뒤 받은편지함/스팸함을 확인해야 합니다. SMTP 미설정·발송 실패 시 성공 안내나 가짜 번호를 반환하지 않습니다.

앱은 Web에서 `http://127.0.0.1:8787`, Android 에뮬레이터에서 `http://10.0.2.2:8787`을 사용합니다. 변경 시 `--dart-define=ACCOUNT_BASE_URL=...`로 지정하세요. 서버는 기존 AI 서버와 함께 실행되며 127.0.0.1로만 바인딩됩니다. 실물 기기·공개 배포는 별도 HTTPS 서버 구성과 접근 제어가 필요합니다.

## 오류·만료 동작

- 코드 유효 시간 10분, 1회 사용. 서버 재시작 시 미완료 인증은 무효화됩니다.
- 코드별 검증 최대 5회, 이메일별 누적 실패 한도와 발송 제한 적용.
- 재발송 간격 60초, 이메일별 시간당 5회, 서버 전체 시간당 30회. SMTP 실패도 제한에 포함됩니다.
- 재발송 요청 시 이전 코드는 무효화됩니다. 새 메일의 코드만 사용하세요.
- 인증번호 원문은 응답/로그/디스크에 저장하지 않습니다. 서버 메모리에는 해시와 만료 정보만 유지합니다. 새 비밀번호는 서버로 보내지 않고 기기에서 salt+PBKDF2로 저장합니다.
- 성공 후 로그인 유지 정보가 해제되며 새 비밀번호로 다시 로그인합니다. 다른 실행 탭의 메모리 세션까지 중앙에서 폐기하는 기능은 없습니다.
- 인증 직후 기기 저장 실패 또는 네트워크 응답 유실 시 기존 비밀번호가 유지될 수 있습니다. 새 코드를 요청하여 다시 진행하세요.

## 검증

`flutter test test/password_reset_test.dart`, `flutter analyze`, `cd server && npm test`.
테스트는 대역 메일 발송과 HTTP 서버를 사용하여 외부 메일을 보내지 않습니다. 실제 SMTP 수신은 발신 설정 완료 후 별도로 확인해야 합니다.
