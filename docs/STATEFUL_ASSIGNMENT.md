# Stateful widgets 과제

이전 제출(main `90bf6e83a099535d9216a7e82a97f37964d1b37f`)의 운동 Assist 앱을 확장했다.
별도 OUTIME 디자인 프로젝트가 아니라, 이 저장소의 기존 로그인·운동선택·Plan·운동분석·AI 흐름을 기반으로 한다.

## 새로 구현한 상태 변화

| StatefulWidget | 화면 내부 상태 | 사용자 이벤트와 화면 변화 |
|---|---|---|
| `NotificationSettingsScreen` | 저장된 설정, 수정 중인 초안, 이탈 확인 상태 | 스위치·체크박스·시간 선택 → `setState()` → 선택 상태 및 저장 버튼 갱신 |
| `SportPickerSheet` | 선택 종목 집합, 검색 입력 | 검색·체크 → `setState()` → 필터 목록과 선택 개수 갱신 |

`StatefulShellRoute`만 사용하는 것으로 과제를 설명하지 않는다. 위 두 화면이 직접
`StatefulWidget`을 상속하고 `State` 클래스에서 변경 가능한 상태와 생명주기를 관리한다.
기존 로그인, 회원가입, 위치 입력, 운동분석, AI 채팅의 StatefulWidget도 유지했다.

## 상태 관리와 생명주기

1. `initState()`에서 저장된 값이나 `initialSelection`을 읽어 화면의 초기 상태를 만든다.
2. 클릭 이벤트에서 `setState()`를 호출한다. Flutter는 해당 State의 `build()`를 다시 실행한다.
3. 수정 중인 설정은 `_draft`에만 반영된다. **설정 저장**을 눌러야 `AppState`에 전달한다.
4. `AppState`의 `ChangeNotifier`는 다른 화면에도 필요한 저장 데이터와 테마 등을 공유한다.
5. 검색창의 `TextEditingController`는 `dispose()`에서 정리한다.
6. 시간 선택창·이탈 확인창·운동 선택창을 기다린 뒤에는 `mounted`를 확인해 이미 닫힌 화면을 갱신하지 않는다.

```dart
onChanged: (value) => setState(() {
  _draft = _draft.copyWith(enabled: value);
}),
```

설정 객체는 불변 값이며, `copyWith`로 새 값을 만든다. 값 비교로 변경 여부를 판단하기 때문에
스위치를 원래 상태로 돌리면 저장 버튼도 다시 비활성화된다.

## 3분 시연 순서

1. 앱을 실행하고 데모 ID `student`, 비밀번호 `demo`로 로그인한다.
   기존 데모 인증은 미등록 ID와 비어 있지 않은 비밀번호를 허용한다. 실제 서버 계정이 아니다.
2. **선호 운동 추가 / 수정** → 농구 체크 → 검색창에 `자전거` 입력 → 자전거 체크.
   검색으로 농구가 숨겨져도 선택 개수는 2개다. **완료** 후 두 종목이 표시된다.
3. 다시 선택창을 열고 종목을 바꾼 다음 **취소**한다. 기존 선택이 유지된다.
4. 상단 **종 아이콘(알림 설정)**을 누른다. 팀·크루 소식 등을 변경하면 저장 버튼이 활성화된다.
5. 전체 알림을 끄면 세부 설정이 비활성화되고, 다시 켜면 기존 선택이 유지된다.
6. 운동 시작 전 **30분 전**을 추가하고 **방해금지 시간**을 켜 시간 선택창을 연다.
7. **설정 저장** → 뒤로 → 다시 열기. 저장한 설정이 유지된다.
8. 설정을 다시 바꾼 뒤 뒤로 가기 → **계속 수정** / **변경 버리기**의 차이를 확인한다.

직접 주소 `/settings/notifications`로 진입해도 로그인이 필요하며 로그인 후 요청한 화면으로 복귀한다.
선택 종목이 0개이거나 검색 결과가 없을 때도 안내를 표시한다.

## 제출 파일과 실행

- `lib/`: 진입점, 화면, 상태 모델, 테마, 라우터를 포함한 Flutter 소스.
- `pubspec.yaml`: 프로젝트와 의존성 선언. `pubspec.lock`도 포함한다.
- 이미지·폰트 assets를 사용하지 않아 `assets/` 디렉터리는 필요 없다. 아이콘은 Flutter Material Icons다.
- `test/`: 기존 라우팅 회귀 테스트와 새 상태 변화 테스트.
- `docs/VALIDATION.md`: 실제 검증 결과와 제한 사항.

```bash
flutter pub get
flutter run
# 자동 검증
flutter analyze
flutter test
flutter build web
```

Flutter 3.44 이상, Dart 3.12 이상이 필요하다. 제출 시 저장소를 **2026년 12월 25일까지 공개**로 유지한다.

## 구현 범위

알림 설정은 UI와 상태 관리 프로토타입이다. 실제 푸시 발송, 운영체제 권한 요청,
알림 스케줄러, 서버 저장은 구현하지 않았다. 사용자별 알림 설정은 같은 앱 실행 중 로그아웃·재로그인에는
유지되지만 앱 재시작·웹 새로고침 시 초기화된다. 기존 종목/장소 데이터의 세션 관리 방식은 유지했다.
날씨·AI 응답은 기존 더미 데이터이며, 팀/크루 알림 항목이 실제 커뮤니티 구현을 의미하지 않는다.
