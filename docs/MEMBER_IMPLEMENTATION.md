한상민 담당은 회원가입·로그인·내정보. 공통 설문은 성별/나이/키, 관심 운동, 활동 지역과 장소, 시간대, 커뮤니티 목적, 마지막 자기소개. 종목별로 빈도/시간과 농구(선수 경험·국적·실력·포지션), 러닝(페이스·거리·워치), 축구(주발·실력·주/부포지션·축구/풋살·선수 경험)를 받는다. 이전 대화에 따라 알림은 가입 필수 질문에서 제외하고 앱 내 설정으로 제공한다.

## 아키텍처와 계약
- View → MemberController → MemberRepository → MemberStore/PasswordHasher.
- 회원 객체는 불변 값이며 컬렉션을 방어 복사한다. 화면 초안은 저장 전 공유 프로필에 반영되지 않는다.
- SharedPreferences에 버전 있는 단일 JSON 스냅샷을 저장한다. 저장 성공 후에만 메모리 상태를 확정한다. 비밀번호는 salt + PBKDF2 검증값으로 보관한다. 이 저장소는 운영 인증/보안 저장소가 아니며, 실제 개인정보·재사용 비밀번호를 입력하지 않는 로컬 데모다.
- Controller는 중복 명령을 차단하고 실패/로딩을 노출한다. 앱 시작 시 복원 완료 전 라우터를 만들지 않는다. 로그인 유지 OFF면 재시작 시 로그인 화면. 로그아웃은 세션을 저장소에서도 제거한다.
- 기존 AppState는 회원 컨트롤러를 연결하는 호환 계층이다. 종목/설문/지역은 현재 계정 프로필에서 읽는다. 기존 홈·매치·지도·랭킹 흐름을 보존한다.
- 공개 경로: 로그인/가입/데모선택/비밀번호재설정 안내. 가입 직후 pending 프로필은 설문으로 유도, 나중에는 deferred로 홈 진입, 완료는 complete. 외부 복귀 URL은 거부한다.
- 내정보: 편집, 종목별 자가 평가와 미배정 티어, 즐겨찾기, 팀·신청 목록, 알림 설정, 테마, 로그아웃. 데모 계정에만 DEMO 팀/티어/신청 예시 제공. 실제 계정은 빈 상태. 신청 취소는 로컬 시연이며 팀 승인 권한은 제공하지 않는다.
- 메일/실제 푸시/선수 인증/랭킹 산정/서버 인증은 연결점만 남기고 구현 완료로 표현하지 않는다.

## 다른 담당과 연결할 지점

1. 서버 담당: `MemberRepository`의 가입/로그인/복원/저장/로그아웃 API를 서버 인증 저장소로 교체하고, 토큰 보관·실제 이메일 확인/복구를 구현한다. 현재 로컬 비밀번호 검증을 서버 인증으로 오해하지 않도록 별도 단계로 전환한다.
2. 커뮤니티 담당: `team_screens.dart`의 DEMO 목록을 팀/신청 API로 교체한다. 현재 취소 상태도 서버 변경이 아니다.
3. 매칭 담당: 현재 회원의 `sports`, `answers`, `common`을 사용한다. 빈 값·미정·응답 안 함을 허용하고, 선수 경력/자가 평가와 검증된 티어를 구분한다.
4. 랭킹 담당: 내정보의 DEMO 티어 대신 서버의 종목별 티어를 연결한다. 새 계정은 미배정 상태를 유지한다.
5. 알림 담당: `notifications`, `reminder`, `quietEnabled/quietStart/quietEnd`를 읽어 권한 요청·푸시 토큰·스케줄 발송을 구현한다. 저장된 선호 자체는 알림 발송을 뜻하지 않는다.
